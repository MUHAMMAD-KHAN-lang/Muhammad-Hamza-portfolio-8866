engineering system design**, with **UAV/UAS and drone engineering** as the principal application
domain.

The work starts from governing physics rather than from a parts list: establish what the system must
do, express that behaviour mathematically, choose an architecture that satisfies it, design the

## Engineering Approach

```
Understand → Model → Design → Simulate → Integrate → Test → Optimize
```

| Stage | Description |
|---|---|
| 01 — Understand | Requirements, constraints, physical behaviour and system objectives |
| 02 — Model | Translate the real-world problem into mathematical and computational models |
| 03 — Design | System architecture, components, physical structure and control approach |
| 04 — Simulate | Analyse expected behaviour before physical implementation |
| 05 — Integrate | Combine mechanical, electrical, embedded, software, communication and control subsystems |
| 06 — Test | Compare actual behaviour with modeled and expected performance |
| 07 — Optimize | Improve efficiency, robustness, scalability, reliability and overall performance |

**Engineering philosophy:** *Understand the system before optimizing the system.* Engineering is not
only about selecting components; it is about understanding how mathematics, physical behaviour,
electronics, software, control, mechanics, communication, and system architecture interact as a
complete system.

## Website

This repository **is** the website. It is a dependency-free static site published with GitHub Pages.

```
.
├── index.html                      # Landing page
├── profile.html                    # Engineering profile (web CV)
├── 404.html
├── README.md
├── DEPLOYMENT.md                   # Setup, publishing and maintenance guide
├── robots.txt / sitemap.xml
├── .nojekyll                       # Serve files verbatim, no Jekyll processing
├── assets/
│   ├── branding/                   # ★ EMH mark, logo variants, favicon, OG cover
│   ├── images/                     # project figures
│   ├── icons/
│   └── documents/
│       └── Muhammad_Hamza_CV.pdf   # ← drop the CV here
├── css/
│   └── style.css                   # Complete design system, one file
├── js/
│   ├── config.js                   # ★ ALL configuration lives here
│   ├── main.js                     # Motion system, navigation, brand bindings
│   ├── github.js                   # Automatic project discovery + filtering
│   └── projects.js                 # Project explorer and detail pages
├── data/
│   ├── projects.json               # Auto-generated repository snapshot
│   └── project-details.json        # Optional hand-written project write-ups
├── projects/
│   └── index.html                  # Project explorer + /projects/?repo=<name>
└── .github/
    ├── scripts/fetch-projects.mjs
    └── workflows/update-projects.yml
```

**How the project list stays current** — a hybrid architecture chosen for reliability:

1. A GitHub Actions workflow regenerates `data/projects.json` daily. The page reads it instantly, with
   no API rate limit and no dependency on GitHub being reachable from the visitor's network.
2. In parallel the page queries the public GitHub API in the background, so a repository created
   minutes ago appears immediately rather than waiting for the next sync.
3. If both fail, a professional fallback message and a direct GitHub link are shown — never a broken
   or empty section.

No backend. No build step. No tokens in client-side code. Public repository data only.
